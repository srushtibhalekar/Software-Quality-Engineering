# Day 2: Software Development Life Cycle (SDLC)

## 1. What Is SDLC?

SDLC stands for **Software Development Life Cycle**.

It is a step-by-step process used to plan, develop, test, release, and maintain software.

**Example:** When developing an online banking application, the team first understands customer requirements, designs the application, writes code, tests the features, and finally releases the application to users.

## 2. Why Is SDLC Important?

SDLC is important because it helps to:

- Organize the software development process.
- Understand customer requirements.
- Manage project time and resources.
- Identify risks early.
- Improve software quality.
- Deliver software systematically.
- Make software maintenance easier.

## 3. Phases of SDLC

SDLC commonly includes the following seven phases.

### Phase 1: Planning

In this phase, the team decides the project goals, budget, timeline, resources, and feasibility.

**Example:** A company decides to develop an online banking application and estimates the time and cost required.

### Phase 2: Requirement Analysis

The team collects and studies the customer's requirements.

Requirements describe what the software should do.

**Example:** The banking application must allow users to log in, check their account balance, and transfer money.

**Tester’s role:**
- Review requirements.
- Identify unclear or missing information.
- Ask questions about expected behaviour.
- Identify possible test scenarios.

### Phase 3: Design

In this phase, the team prepares the software design, database structure, architecture, and user interface.

**Example:** Designers prepare the banking application's login page and account dashboard.

**Tester’s role:**
- Review designs.
- Identify possible usability issues.
- Start preparing test scenarios and test conditions.

### Phase 4: Development

Developers write the code according to the requirements and design.

**Example:** Developers implement login, account balance, and money transfer features.

**Tester’s role:**
- Prepare test cases.
- Prepare test data.
- Understand how the features should work.
- Coordinate with developers when clarification is needed.

### Phase 5: Testing

Testers check the application to identify defects and verify that it meets the requirements.

**Example:** A tester checks whether a user can log in with valid credentials and whether an invalid password displays an appropriate error message.

**Tester’s activities:**
- Execute test cases.
- Compare expected and actual results.
- Report defects.
- Retest fixed defects.
- Perform regression testing when needed.

### Phase 6: Deployment

The software is released into the production environment so that users can access it.

**Example:** The banking application becomes available to customers.

**Tester’s role:**
- Support release checks.
- Perform smoke testing when required.
- Verify critical functions in the deployed environment.

### Phase 7: Maintenance

After release, the team fixes defects, updates features, and improves the software.

**Example:** If customers report an issue with money transfers, the team investigates and fixes it.

**Tester’s role:**
- Retest fixes.
- Perform regression testing.
- Verify changes.
- Check that existing features continue to work.

## 4. SDLC Example: College Management System

| SDLC Phase | Example |
|---|---|
| Planning | Decide to build a college management system. |
| Requirement Analysis | Identify requirements for student registration, attendance, and results. |
| Design | Design the database and application screens. |
| Development | Developers write the application code. |
| Testing | Test registration, attendance, and result calculations. |
| Deployment | Release the system for college staff and students. |
| Maintenance | Fix defects and update features when required. |

## 5. What Is the Role of a Tester in SDLC?

Testing is not limited to the testing phase. Testers can contribute throughout the development life cycle.

- **Planning:** Understand project scope and quality risks.
- **Requirement Analysis:** Review requirements and identify missing details.
- **Design:** Review designs and prepare test scenarios.
- **Development:** Prepare test cases and test data.
- **Testing:** Execute tests and report defects.
- **Deployment:** Support release checks and smoke testing.
- **Maintenance:** Retest fixes and perform regression testing.

Early testing activities can help identify problems before they become more expensive to fix.

## 6. Advantages of SDLC

- Provides a structured development process.
- Improves communication among team members.
- Helps manage time and resources.
- Makes requirements easier to track.
- Supports early identification of risks.
- Helps maintain software quality.

## 7. Disadvantages of SDLC

- Some approaches require significant documentation.
- Changes to requirements can increase time and cost.
- Following a rigid process may slow down projects that need frequent changes.
- Poor planning can affect the entire project.

The impact depends on the SDLC model used and how the project is managed.

## 8. SDLC vs. STLC

| SDLC | STLC |
|---|---|
| Stands for Software Development Life Cycle. | Stands for Software Testing Life Cycle. |
| Covers the overall software development process. | Focuses on software testing activities. |
| Includes planning, requirements, design, development, testing, deployment, and maintenance. | Includes test planning, test analysis, test design, environment setup, test execution, and test closure. |
| Involves developers, testers, business analysts, and other team members. | Mainly focuses on testing activities performed by testers and QA teams. |

## 9. SDLC Interview Questions and Answers

### Q1. What is SDLC?

SDLC stands for Software Development Life Cycle. It is a structured process used to develop, test, release, and maintain software.

### Q2. What are the phases of SDLC?

The common phases are planning, requirement analysis, design, development, testing, deployment, and maintenance.

### Q3. Why is SDLC important?

SDLC helps the team organize work, manage resources, understand requirements, identify risks, and deliver quality software.

### Q4. What is the role of a tester in SDLC?

A tester reviews requirements, prepares test scenarios and test cases, executes tests, reports defects, retests fixes, and checks existing functionality after changes.

### Q5. When does testing start in SDLC?

Testing activities can start during requirement analysis. Testers can review requirements and prepare test scenarios before the software is ready for execution.

### Q6. Is testing performed only after development?

No. Testers can review requirements and designs and prepare test cases during development. Actual test execution depends on the availability of the software and test environment.

### Q7. What happens during the maintenance phase?

The team fixes defects, updates features, improves performance, and maintains the application after release. Testers verify fixes and check that existing features still work.

### Q8. What is the difference between SDLC and STLC?

SDLC covers the entire software development process, whereas STLC focuses on the activities required to test the software.

### Q9. Can a project skip the testing phase?

Skipping testing increases the risk of defects reaching users. Testing activities should be planned according to the project's risks and quality requirements.

### Q10. Who is involved in SDLC?

Depending on the project, the team may include project managers, business analysts, designers, developers, testers, DevOps engineers, and customers or other stakeholders.
